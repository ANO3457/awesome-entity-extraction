# Community contribution entry points

Use GitHub Issues for bounded work and bugs; use Discussions for open-ended
questions and feedback. A prior issue is optional—a focused PR is welcome.

## Current entry points

- [Pick a good first issue](https://github.com/shivamnegi92/awesome-entity-extraction/issues?q=is%3Aissue+is%3Aopen+label%3Agood-first-issue)
- [Browse all open issues](https://github.com/shivamnegi92/awesome-entity-extraction/issues)
- [Propose a task card](https://github.com/shivamnegi92/awesome-entity-extraction/issues/new?template=task_card.md)
- [Suggest a resource or report a correction](https://github.com/shivamnegi92/awesome-entity-extraction/issues/new/choose)
- [Discuss a use case or chooser feedback](https://github.com/shivamnegi92/awesome-entity-extraction/discussions)
- [Read contribution requirements](CONTRIBUTING.md)

Issue templates should collect only the minimum context needed to act. Never
include private/customer/health text, credentials, or API keys. For Field Guide
work, synthetic or clearly redistributable fixtures only.

Maintainers should close or re-scope an issue if it becomes stale, duplicate,
unsafe, or too broad. Keep a short, real issue list; don't seed placeholder
"help wanted" requests just to make the repo look active.
